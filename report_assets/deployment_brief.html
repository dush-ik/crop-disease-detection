1. Purpose

This tool is a decision-support aid, not an automated diagnostic system. It takes a photograph of a crop leaf and suggests possible diseases, along with a confidence score and a visual explanation of what the tool "looked at" to make its suggestion. It is designed to help extension workers triage and prioritize cases quickly — not to replace expert diagnosis or guide treatment decisions on its own.

2. How It Works

  1. Upload a photo of a single leaf.
  2. The tool returns its top 3 most likely diseases, each with a confidence percentage.
  3. A heatmap overlay (Grad-CAM) shows which part of the leaf image most influenced the prediction — useful for sanity-checking whether the tool is focusing on an actual lesion/spot rather than something irrelevant in the photo.

This runs as a simple local demo (built with Gradio); no internet connection or account is required to use it.

3. How Much to Trust It

  • On standardized, well-lit, single-leaf photographs (similar to the conditions used to train the tool), it correctly identifies the disease over 99% of the time, across 38 disease/healthy categories spanning 14 crop types.
  • Confidence scores have been calibrated so that, under those same conditions, a "90% confident" prediction is genuinely right about 90% of the time — making the confidence score a meaningful signal for deciding when to double-check a result with an expert.
Important limitation — real-world field photos: When tested on real field photographs, accuracy dropped substantially, and the tool was sometimes confidently wrong rather than appropriately unsure. See Section 6 for verified evidence. Do not rely on the confidence score alone as a "safe" signal when the photo doesn't closely resemble a clean, close-up single-leaf shot.

4. Recommended Usage Workflow

  1. Take a clear, close-up photo of a single affected leaf (plain background if possible, leaf filling most of the frame, good lighting).
  2. Use the tool's top-3 suggestions as a starting point for investigation, not a final answer.
  3. Cross-check the heatmap: if it highlights the visible lesion/spot, that's a good sign; if it highlights background or irrelevant areas, treat the prediction with extra caution.
  4. For any decision affecting treatment, spraying, or economic loss, escalate to a human expert or regional agronomist rather than acting on the tool's output alone.
  5. Do not use this tool to make pesticide or treatment recommendations directly.

5. Known Limitations

  • Covers only 38 disease/healthy categories across the crops in the PlantVillage dataset.
  • Performance is best on photos resembling standardized lab conditions; real field photo accuracy is meaningfully lower (Section 6).
  • No handling yet for multiple diseases in one photo, multiple leaves in one frame, or non-leaf images.
  • Not validated for any specific geographic region, crop variety, or growth stage.

6. Field Generalisation Testing VERIFIED — actually executed

Motivation. As anticipated in the project proposal (Challenges #3 and #7), PlantVillage images are captured under controlled, uniform-background studio conditions. To assess whether the model's near-ceiling test performance (macro-F1 = 0.991) would transfer to real-world usage, the final fine-tuned ResNet-50 was evaluated on a set of independent field images sourced from the University of Georgia's IPM Images / Bugwood.org archive — an agricultural extension image repository entirely separate from PlantVillage.

Method. Six images were selected, each verified against the archive's own disease-label metadata before use, spanning five distinct diseases already present in the model's 38 trained classes. Each image was passed through the identical preprocessing pipeline used for evaluation (resize, ImageNet normalization) and the identical temperature-scaled confidence from the calibration analysis (T = 0.615). All results below were captured live from the running Gradio prototype — not simulated.

Interpretation. This 50% field accuracy (vs. 99.4% on the PlantVillage test set) is consistent with the background-bias risk identified in the proposal: PlantVillage's uniform studio backgrounds (plain black, white, or gray backdrops) may have allowed the model to partially key on background texture rather than relying solely on disease-lesion features — visible directly in Figure 2, where the misclassified apple scab photo itself uses a studio-style backdrop closely resembling PlantVillage's own style, yet was still misclassified. Field photographs with natural backgrounds, soil, and foliage fall outside this learned distribution more broadly. Critically, the confidence-calibration mechanism does not reliably degrade under this distribution shift in every case; three of the six predictions above remained confidently wrong (81–99%) rather than appropriately uncertain, though notably the correct citrus greening prediction (Figure 5, 71%) does show the model can express lower confidence appropriately on harder cases.

Deployment implication: consistent with the project's stated position, this reinforces that the system must be deployed strictly as decision support, not autonomous diagnosis, and that confidence scores alone cannot yet be fully trusted as a reliable escalation signal for out-of-distribution field images.

Recommended future work

  • Background-replacement augmentation — the dataset's pre-segmented leaf masks could be composited onto varied real-world backgrounds during training, directly targeting the suspected background-keying behavior.
  • Fine-tuning on real field imagery — supplementing training with a field-condition dataset such as PlantDoc (2,598 real-world images across overlapping crop/disease categories).
  • Larger-scale field evaluation — this test used a modest, illustrative sample (n=6); a statistically robust assessment would require dozens of verified field images per class.
  • Out-of-distribution detection — a mechanism to flag inputs that fall outside the training distribution, rather than relying solely on softmax confidence.

7. Technical Deployment Details

7.1 Deployment Overview & Architecture

  • Model format: PyTorch serialized state dictionary (.pth)
  • Model architecture: ResNet-50 (ImageNet-pretrained backbone, fine-tuned), 23,585,894 total parameters
  • Artifact file: new_saved_models/resnet50_unfrozen_best_state_100p.pth (90.3 MB, verified on disk)
  • Inference engine: PyTorch CPU runtime (no GPU required for inference)
  • Interface: Gradio local web demo (app.py) — a single-process local application accessed via browser, not a REST API

System flow

[User] -> uploads leaf photo via Gradio browser UI
       |
[PIL.Image] -> convert to RGB -> torchvision.transforms (resize 224x224, ToTensor, ImageNet normalize)
       |
[ResNet-50 model] -> load_state_dict(.pth) -> model.eval() -> forward pass (torch.no_grad())
       |
[Post-processing] -> softmax(logits / T) with calibrated temperature T=0.615 -> top-3 classes
       |
[Grad-CAM] -> hook on layer4[-1] -> backward pass on predicted class -> heatmap overlay
       |
[Gradio UI] -> displays top-3 predictions + confidence + Grad-CAM image

7.4 Deployment Risk & Mitigations

  • Memory: torch.no_grad() is used during the main inference pass to avoid building a gradient graph; Grad-CAM separately requires gradients only for its own scoped backward hook.
  • Error handling: confirmed above — invalid/corrupted image uploads raise catchable exceptions rather than crashing silently.
  • Reproducibility risk: the fitted temperature (T=0.615) and checkpoint are tied to this specific training run — if the model is retrained, both the checkpoint path and TEMPERATURE constant must be updated together, or confidence scores will be miscalibrated.
